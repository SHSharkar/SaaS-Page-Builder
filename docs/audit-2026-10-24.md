## 2. Findings

### 2.1 Security

| # | Finding | Evidence |
| --- | --- | --- |
| S1 | Custom domains could be activated without any proof of ownership: `markDomainVerified` set `status = 'active'` and `certificate_state = 'issued'` for any `domainId` in the caller's scope. The TXT token was generated but never checked, so a workspace could claim a hostname it did not control and serve content on it. | `app/server/domains/index.ts` (previous), `app/server/domains/actions.ts` |
| S2 | Stripe webhook verification was a plain HMAC of the request body, not Stripe's `t=<ts>,v1=<hmac(secret, "t.body")>` scheme, and no timestamp tolerance was checked. Real Stripe deliveries would always fail verification, and a replayed body from a naive sender would always pass. | `app/server/webhooks/index.ts`, `app/webhooks/stripe/route.ts` |
| S3 | The `/my-data` erasure rate-limit key was derived on the client from the first 16 characters of the guest contact. That made the limiter trivially bypassable (send different contacts) and pushed a fragment of a guest contact into a Valkey key. | `components/app-shell/workspace-forms.tsx`, `app/server/privacy/actions.ts` |
| S4 | Duplicate `sites.slug` and `site_domains.hostname` inserts surfaced raw Postgres unique-violation errors (and `hostname` is globally unique, so the error leaked the existence of another workspace's domain). | `app/server/sites/index.ts`, `app/server/domains/index.ts` |

### 2.2 Correctness

| # | Finding | Evidence |
| --- | --- | --- |
| C1 | Published-page caching was never invalidated. `resolvePublishedPage` cached `pub:page:<host-or-slug>:<path>` for 120 seconds, while `publishSitePage` deleted `pub:site:<siteId>`; `rollbackPageToVersion` and site status changes deleted nothing. Editors could publish, suspend a site, or roll back, and readers kept seeing the old page. | `app/server/public-site/index.ts`, `app/server/pages/index.ts` |
| C2 | Every draft save appended tracking placements instead of replacing them, so `tracking_placements` grew on each save and the dashboard's placement metric inflated. | `app/server/pages/index.ts` (previous) |
| C3 | The background subsystem was hollow. `scripts/worker.ts` registered `boss.work(kind, async () => {})` for all eight queues; only `sweeper.daily` did anything. Nothing ever enqueued a job, so scheduled publishing, domain verification, import processing, media sweeps, erasure replay, and backups never ran, while the log claimed `worker.job_completed`. | `scripts/worker.ts`, `app/server/jobs/index.ts` |
| C4 | `scripts/restore-backup.ts` was not a restore script: `bun run db:restore` replayed the erasure log and printed "Restore complete", restoring nothing. | `scripts/restore-backup.ts` (previous) |
| C5 | Nothing scheduled the daily sweeper or any other periodic job; there was no `boss.schedule` call anywhere. | `app/server/jobs/index.ts` |

## 3. Fixes Applied

### Gate and tooling

- Split the tooling along its real seams: `scripts/verify-plan.ts` (catalogue, tier planning, change discovery), `scripts/verify-gate.ts` (runner, `latest.json`, journal append, recovery hint), `scripts/verify-log.ts` (journal reader with `--limit`/`--all`). `bun run verify`, `verify:fast`, `verify:code`, `verify:schema`, and `verify:log` map onto them, and `.husky/pre-push` runs the gate.
- `verify-tier.ts` gained `requestedTier()`/`isVerifyTier()`, so `VERIFY_TIER` can force a tier and `VERIFY_TIERS` is a single source of truth.
- `verify-shell.ts` probes both tools, fails with install instructions when absent, and reports real tool output otherwise.
- `scripts/verify-gate.test.ts` covers tier ordering, change discovery, journal round-trips, corrupt journal lines, and history limits.

### Security

- **Domain ownership is real**: `verifyDomainOwnership` resolves `_spb-verify.<hostname>` (injectable resolver for tests), `verifyCustomDomain` walks `pending -> verifying -> active|failed` under the lifecycle table, records the outcome in the audit log, and leaves `certificate_state` at `pending` until TLS provisioning. `markDomainVerified` is gone. `verifyPendingDomains` re-checks unfinished domains on a 15-minute schedule, and `removeSiteDomain` was added so domains can leave the active set.
- **Stripe signatures** are verified with the `t`/`v1` scheme, per-signature constant-time comparison, and a 300-second tolerance (`verifyStripeWebhookSignature`). `verify:authz` now recognises the new guard.
- **Erasure rate limiting** keys on the proxy-derived client IP (`x-spb-client-ip`), with a per-process fallback for non-request contexts. The client no longer sends a key.
- **Duplicate slugs and hostnames** are translated into actionable messages through `isUniqueViolation`, which walks the Drizzle error `cause` chain.

### Correctness

- **Published-page cache**: keys are registered in `pub:index:<siteId>` and dropped by `invalidatePublicSiteCache`. Publishing, rollback, global publishing, and site status changes all invalidate; the reader path is unchanged for cache hits.
- **Tracking placements** are deleted for the page inside the draft-save transaction before the new set is inserted.
- **Background work is real**: `app/server/jobs/handlers.ts` implements one handler per queue (`publishDuePages`, `unpublishDuePages`, `verifyPendingDomains`, `purgeRetiredMedia`, `purgeErasedContacts`, `purgeExpiredKeepWindows`), `JOB_SCHEDULES` installs cron entries through `ensureScheduledJobs`, and `scripts/worker.ts` refuses to start when a declared queue has no handler.
- **Queue catalogue** now only contains queues with a producer and a handler: `import.process` and `backup.snapshot` were removed, since imports run synchronously through the review path and backups are a CLI concern (`db:restore`).
- **Scheduling API**: `schedulePagePublish` plus `schedulePageAction` set `scheduled_publish_at`/`scheduled_unpublish_at`, which the per-minute queues consume.
- **Restore is a restore**: `scripts/restore-backup.ts` parses `--file/--plain/--database-url/--skip-erasure-replay`, decrypts the `bak1:` envelope, applies the dump with `psql`, then replays the erasure log.
- **Worker liveness** is now testable: `scripts/worker-healthcheck.ts` reads `worker_heartbeats` and fails when the heartbeat is stale or the worker stopped claiming work.

### Deployment

- `docker-compose.yml` now matches the documented model: an `x-hardening` anchor (read-only root, tmpfs, dropped capabilities, no-new-privileges, 16 MB × 4 log rotation), explicit memory/PID limits per service, `init: true` and stop grace periods for long-running services, expose-only `web` with the `caddy_ingress_network: coolify` label, fail-fast `${VAR:?}` guards, and a worker health check. `deploy/compose-environment.test.ts` asserts each of these.

### Documents

- `project-scope.md`, `project-foundation-report.md`, `README.md`, `AGENTS.md`, `CLAUDE.md`, `.specify/memory/constitution.md`, `docs/deployment.md`, and both architecture skills were rewritten against the code: real table names, real queues and schedules, real scripts, the four hooks that exist, the one Playwright spec, the actual compose topology, and the `app.account_id` GUC. The two skill copies are byte-identical again.

## 5. Residual Risks (not fixed here)

1. **Self-service erasure is unauthenticated.** Anyone who knows a guest contact value can delete that contact record across workspaces. It is now IP rate limited and audited, but a confirmation link (the `my_data` short-link kind already exists) should gate it.
2. **One-time short links are not consumed.** `short_links.consumed_at` exists and `resolveExpiringShortLink` reads it, but nothing writes it, so `password_reset`/`export` links work until expiry.
3. **`app/server/imports` applies reviewed imports in two transactions**, so a failure between the status update and page creation leaves an `applied` job with no page.
4. **Media purge removes database rows only**; the R2 object for a retired asset is not deleted, and presigned uploads are not verified against sniffed bytes (`sniffImageMimeType`/`inspectImageDimensions` exist but are unused).
5. **Rate limiting is a fixed window** (`INCR` + `EXPIRE`), so a burst can double the allowance across a window boundary. The documents now say so.
6. **`listPlatformTemplates` and `public-site` use the bare pool** through the allowlist. That is intentional for platform-global and SECURITY DEFINER paths but should be re-reviewed if the allowlist grows.
7. **`next.config.ts` keeps `typescript.ignoreBuildErrors`**, so the gate is the only type-safety net; a push without hooks (or with `--no-verify`) skips it entirely.
8. **`verify:unused` is quiet.** Knip reports no unused exports although `sniffImageMimeType`, `inspectImageDimensions`, and `isPrimaryPlatformHost` are exported but never called outside tests; the entry globs (`scripts/*.ts`, all `app/**` page files) are too broad to catch this class of dead code.
